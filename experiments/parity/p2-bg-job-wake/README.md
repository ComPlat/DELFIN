# p2 — a background job reports when it ends

Measures the package's claim on DELFIN's own entry points: a command started in
the background reports back when it ends (exit code, where its output is), the
agent does not poll it or chain sleeps, and the wait is bounded by what the
caller asked for.

    PYTHONPATH=. python experiments/parity/p2-bg-job-wake/scenario.py \
        --all --label before --out experiments/parity/p2-bg-job-wake/before.json

`before.json` / `after.json` hold, per variant, REACHED / USED / CORRECT plus
the waiting cost (model calls, wake turns, wall seconds, and how many seconds
after the job ended the session noticed it). The harness drives
`cli.main([...])` — `delfin-agent chat -p ... --output-format stream-json`,
`delfin-agent run`, `delfin-agent chat` — with the real engine, tool loop and
permission gate; only the model's replies are scripted. `scenario.py`'s module
docstring states the one substitution it makes (how a live process joins the
job registry, because this host's cage refuses every `bash_background` command)
and why the wake path itself is untouched by it.

`expected()` states each variant's promised answer from the flag's own help
text and the doors' code paths, never from what the tree happens to do, so no
variant can be made green by moving the goal.

`.runs/` holds the scratch world each variant runs in and the JSON it reports; it is
regenerated by every run and is not committed.
